# 庫存帳本 · 欠料盤點工具

**庫存表只丟一次，之後只要上傳進貨表就會自動累加庫存；上傳工單 BOM 加台數，就能看缺料與可做幾台。**

> 🔒 全程在你的瀏覽器本機運算與儲存，資料不會上傳到任何伺服器。

線上使用：**https://sonicliao0204.github.io/inventory-shortage-checker/**
原始碼：https://github.com/sonicliao0204/inventory-shortage-checker

---

## 一、怎麼用（三個步驟）

| 步驟 | 做什麼 | 多久做一次 |
|---|---|---|
| **1 基準庫存** | 上傳一次倉庫現有數量，建立起點 | **只做一次**（重新盤點時再做） |
| **2 進貨入帳** | 上傳進貨表 → 自動累加到庫存、記錄入帳時間 | 每次進貨 |
| **3 生產工單** | 上傳工單 BOM ＋ 填台數 → 看缺料 → 確認開工才扣料 | 每張工單 |

### 帳本狀態列（最上方）
隨時顯示：料號數、基準建立時間、**最後入帳時間**、進貨筆數、已開工工單數，以及三個動作：匯出備份／匯入備份／重設帳本。

### 庫存怎麼算
```
目前庫存 = 基準庫存 ＋ 進貨累計 − 已扣料
```
庫存不直接存一個數字，而是由「基準＋流水」推算。好處是可稽核、可撤銷、重算不會累積誤差。庫存明細表會把這三項分開列出，並標出**最後入帳時間與單號**。

## 二、三個關鍵機制

### ① 進貨去重（不會重複累加）
- 進貨表**有單號欄** → 以「**進貨單號＋料號**」為鍵，同一筆只算一次。
- 進貨表**沒有單號欄** → 以「**檔案內容指紋＋料號＋行序**」去重，同一份檔案重傳會整批跳過。

重傳時畫面會顯示「本次入帳 0 筆 · 跳過重複 N 筆（共 X 件）」，數量不會變。

### ② 工單先模擬，確認才扣料
上傳 BOM 與台數後，按「模擬缺料」只做試算，**庫存完全沒動**。
看清楚缺料與可做台數後，按「**確認開始生產**」才會扣料。扣料只扣**原料（葉節點）**——半成品是廠內組裝，其子件已展開計算，不重複扣。

**台數必須自己填。** 若只沿用 BOM 裡的舊「生產數量」而沒手動填，扣料按鈕會鎖住，避免誤扣。

### ③ 生產紀錄可撤銷
每張開工的工單都列在「生產紀錄」，按「撤銷」會把扣掉的料**全部加回庫存**，等於回沖。

## 三、資料存在哪裡

| 項目 | 說明 |
|---|---|
| 平時 | 存在這台電腦的瀏覽器（localStorage），關掉再開還在 |
| 換電腦／清快取 | 按「**匯出備份**」下載 JSON，到新環境按「**匯入備份**」還原 |
| 無痕模式 | 無法長期儲存，畫面會跳黃色警告，請每次收工前匯出備份 |

**重設帳本**會清空基準、進貨與生產紀錄，且無法復原（有二次確認）。

## 五、計算邏輯

- **需求量**＝Σ（台數 × 單位用量），多階 BOM 逐層展開。
- **缺料量**＝max(0, 需求量 − 現有庫存)。
- **可生產台數**：由 BOM 遞迴推算，葉節點取可用量，總成取「自身庫存 ＋ min(子件可支撐台數 ÷ 單位用量)」。
- **補料階梯**：每次只補「達到下一台還不夠」的採購件，看補完能跳到幾台。
- **狀態**：缺料／待組裝／足夠／無需求(呆滯)／無資料。
